> 이 문서를 읽은 AI는 아래 내용을 전제로 대화를 시작한다.
> 최종 업데이트: 2026-07-21 (지출 항목 CRUD + 입력 검증 완료 시점)

## 0. 이 문서를 읽은 AI가 가장 먼저 할 일

1. `agents/` 폴더의 모든 md 파일 내용을 참고해 작업한다 (아래 5장 참고)
2. 작업 시작 전 **환경 상태부터 확인**한다 (컴퓨터가 바뀌었을 수 있음)
3. 새 개념은 반드시 설명하고 넘어간다 (사용자는 React·백엔드 초보)
4. **요청받은 것만 만든다.** 마음대로 기능을 확장하지 않는다

### ⚡ 환경 변경 신호 — 자동 대응 규칙

사용자가 아래처럼 말하면, **묻지 말고 곧바로 6-1장(새 환경 세팅)을 안내**한다.

- "노트북으로 하고 있어"
- "본가에서 하고 있어" / "컴퓨터 바꿨어"
- "환경이 바뀌었어" / "새 컴퓨터야"

**대응 순서** (한 단계씩, 사용자 확인 받으며 진행):

```
① 프로젝트 폴더가 있는지 확인      → 없으면 clone부터
② 브랜치 확인 (git switch N021_김동환)
③ git pull로 최신 상태 맞추기
④ node_modules 있는지 확인        → 없으면 npm install (client, server 각각)
⑤ server/.env 있는지 확인         → ⚠️ git에 없으므로 새 환경에선 반드시 다시 만들어야 함
⑥ 서버·React 각각 실행해서 동작 확인
```

**⑤가 가장 자주 놓치는 지점이다.** `.env`는 `.gitignore`로 막혀 있어
clone/pull해도 따라오지 않는다. 없으면 Supabase 연결이 실패하므로,
새 환경이라면 반드시 먼저 확인하고 만들도록 안내할 것.

## 1. 프로젝트 개요

**서비스명**: 홈키퍼 (HomeKeeper)
**슬로건**: "집에 나가는 돈, 이제 신경 쓰지 마세요"
**설명**: 월세·관리비·공과금부터 보증금 반환까지, 전월세 세입자가 집에 나가는 돈을 관리하는 서비스
**타겟**: 첫 자취를 시작하는 사회초년생·대학생
**정체성**: 법률 자문이 아니라 **'일정·지출 관리자 + 공식 링크 연결자'**

**가계부와의 차별점**
- 세입자 맥락(월세·관리비·보증금)을 알기 때문에, 단순 기록이 아니라 판단을 목표로 함
- 고정비는 자동, 변동비만 확인
- 계약 만료 시 돌려받을 돈까지 정산 (향후)

**부트캠프 프로젝트**이며, 매일 PR과 회고 제출이 필요하다.

## 7. ⚠️ 반드시 알아야 할 함정들 (실제로 겪은 것)

### 7-1. "코드를 썼다"의 네 가지 상태

이것들이 **모두 다르며 각각 확인해야 한다**:

```
코드를 썼다 ≠ 파일에 저장됐다 ≠ 의도한 위치에 들어갔다 ≠ 서버에 반영됐다
```

실제로 겪은 사례:
- DELETE API가 `Cannot DELETE` 에러 → **코드가 파일에 아예 없었음**
- 수정 버튼(✏️)을 눌렀는데 삭제 확인창이 뜸 → **삭제 버튼 태그 안쪽에 중첩**되어 있었음
- 서버 검증이 안 걸림 → 코드는 정확했으나 **서버를 재시작하지 않음**
- App.jsx 코드가 통째로 사라짐 → **Ctrl+Z가 여러 번 눌림**

**대응**: 코드를 붙여넣은 뒤 `Ctrl+F`로 검색해 실제로 있는지 확인하고,
서버 코드라면 재시작까지 마친 뒤 다음으로 넘어간다.

### 7-2. 서버는 재시작해야 반영된다

React(`npm run dev`)는 저장하면 자동 반영되지만,
**Express 서버는 `Ctrl+C` → `node index.js`로 재시작**해야 코드가 반영된다.

### 7-3. 환경이 바뀌기 전에는 반드시 push

노트북에서 작업하고 push하지 않아, 다음 날 본가에서 처음부터 다시 만든 적이 있다.
**작업이 끝나면 무조건 push한다.**

### 7-4. .eq() 없는 delete/update는 위험

```javascript
.delete().eq("id", id)   // ✅ 해당 항목만
.delete()                // ❌ 전체 삭제됨
```

### 7-5. 에러 메시지가 가리키는 줄이 진짜 원인이 아닐 수 있다

에러는 68번 줄을 가리켰으나, 실제 원인은 51번 줄의 `return` 뒤 여는 괄호 누락이었다.
(자바스크립트 자동 세미콜론 삽입) → 에러 위치 **위아래를 함께 볼 것**

### 7-6. clone하면 기본 브랜치만 온다

작업물은 `N021_김동환` 브랜치에 있다. clone 후 `git switch N021_김동환` 필수.

## 10. 하루 마무리 절차

사용자가 "마무리하자"고 하면 `agents/skill_wrapup.md`대로 진행한다.

1. **push·PR** (`.env`가 목록에 없는지 확인 필수, PR은 팀 양식으로)
2. **회고**: [오늘 잘한 일] [아쉬운 일] [다음에 다시 한다면?]
3. **작업 정리**: 오늘 한 것 / 어려웠던 것·중요한 것 / 내일 할 것

**각 단계가 끝나면 사용자에게 다음으로 넘어갈지 물어본다.**

### PR 본문 양식 (팀 규칙)

```
## 완료한 작업 목록
## 설계한 내용
## 가장 막혔던 순간
## 새로 알게 된 것
## 다르게 한다면
```
